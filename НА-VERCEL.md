# Как выложить сайт Temka Studio на Vercel

Подготовленный архив: **Temka-Studio-Vercel-1.5.6.zip**. Это статический HTML/CSS/JS-сайт, поэтому npm/Node и сборка для него не нужны. Vercel рекомендует для таких сайтов `Other`, пустой Build Command и корневую Output Directory `.`. [1](https://vercel.com/docs/builds/configure-a-build)

## 1. Сначала распакуй сайт

ПКМ по ZIP → «Извлечь всё». В папке должны быть:

```
index.html
styles.css
app.js
site-config.js
hardware.css
hardware-data.js
hardware-check.js
HARDWARE.md
vercel.json
assets/
```

Остальные Markdown-файлы и tests тоже можно оставить. **Загружай содержимое распакованной папки, не сам ZIP.** Не путай его с `TemkaLauncher-1.5.6-sources.zip`.

## 2. Создай отдельный репозиторий сайта

1. На GitHub нажми **+ → New repository**.
2. Назови, например, `temka-studio-site`. Имя — пример, доступность не проверялась.
3. Выбери видимость, подходящую тебе, создай репозиторий. Секретов в пакете нет.
4. Нажми **uploading an existing file** на пустой странице либо **Add file → Upload files**.
5. Перетащи распакованные файлы и папку `assets`, сохрани структуру. В корне репозитория должен находиться именно `index.html`, а не ZIP и не ещё одна внешняя папка.
6. Нажми **Commit changes** в ветку `main`.

**Не заменяй этим сайтом репозиторий `TEMKALAUCHER`.** Лаунчер остаётся в своём репозитории.

## 3. Подключи репозиторий в Vercel

1. Открой https://vercel.com и войди в свой аккаунт, например через GitHub.
2. Выбери подходящий своему проекту тариф и проверь его действующие условия. Бесплатность любого коммерческого проекта здесь не обещается.
3. **Add New → Project**.
4. В **Import Git Repository** найди репозиторий сайта и нажми **Import**. При первом подключении предоставь Vercel доступ только к нужному репозиторию. Если его не видно — проверь доступ GitHub-интеграции и выбранный аккаунт/team.

## 4. Параметры проекта

| Поле | Значение |
|---|---|
| Project Name | Например `temka-studio`; если занято, выбери другое |
| Framework Preset | **Other** |
| Root Directory | Корень репозитория, где `index.html` |
| Build Command | **Override включён, поле пустое** |
| Install Command | Пустое; зависимости устанавливать не нужно |
| Output Directory | **`.`** — одна точка |
| Environment Variables | Не нужны |

Это соответствует официальной инструкции для статических проектов. Пакет также содержит `vercel.json` с пустыми командами, отключённым framework detection и `outputDirectory: "."`. [1](https://vercel.com/docs/builds/configure-a-build)

Не выбирай Next.js, Vite и `npm run build`: этот сайт не требует их. Не указывай `dist`, такой папки для публикации здесь нет.

## 5. Нажми Deploy

Дождись статуса **Ready**, затем **Visit**. Vercel покажет фактический адрес проекта. Имя домена заранее не гарантируется.

Проверь после публикации:

- главная нормально оформлена, изображения/шрифты и CSS не дают 404;
- «Проверить ПК» открывает нужную секцию;
- полные модели из подсказок выбираются, результат показывает черновую оценку;
- неизвестный Xeon/GPU не выдаётся за гарантированно подходящий;
- вишлист добавляется и сохраняется после обновления страницы;
- Telegram ведёт на `https://t.me/temka_play_official1`;
- Windows-ссылка ведёт на настоящий опубликованный релиз. Пока 1.5.6 не выпущена, корректно видеть 1.5.5;
- меню работает на телефоне.

## Если не получилось

- **404 главной:** `index.html` не в выбранной Root Directory; проверь внешнюю вложенную папку и Output Directory `.`.
- **Пусто/без оформления:** загрузились не все файлы или нарушена структура `assets`. Имена на хостинге чувствительны к регистру.
- **Ошибка npm / package.json:** выбран не тот framework или включена лишняя команда. Поставь Other и пустые Build/Install.
- **Репозиторий не виден:** проверь доступ Vercel GitHub App именно к репозиторию сайта.
- **Друзья не заработали:** это ожидаемо без backend. Хостинг статического сайта не подключает базу друзей лаунчера и SMTP.
- **Версия скачивания старая:** сначала убедись, что новый релиз опубликован с установщиком, затем обнови страницу. При недоступности GitHub API используется проверенная резервная ссылка.

Если меняешь параметры после первого развёртывания, выполни новый Deploy/Redeploy и проверь именно Production deployment. Не публикуй SMTP-пароли, `service_role`, `sb_secret` и пароли базы ни в файлах сайта, ни в его клиентских переменных.

Я не выполнял вход и Deploy в твоём аккаунте. Подготовлены файлы и инструкция; дальше действия выполняешь ты.
